9 天北疆自驾的行程 + 房费 + 车费 + 分账工具。手机浏览器打开即用,**装到主屏后完全离线可用**(禾木、喀纳斯、禾木→贾登峪那几段没信号也能记账)。

## 一、为什么要挂到网上,不能直接发 HTML 文件?

iOS 的「文件」App 打开 `.html` 走的是 **QuickLook 预览**,它**不执行 JavaScript**。
这个工具的页面内容全部由 JS 生成,所以 iOS 同伴直接双击文件只会看到**一片空白**。

安卓 / 电脑不受影响,但既然要发给大家,统一挂到网址上最省事 —— 而且挂上去之后才能装主屏、才能离线。

## 二、部署到 GitHub Pages(免费,10 分钟)

### 1. 建仓库

1. 登录 https://github.com ,右上角 **+** → **New repository**
2. Repository name 随便填,比如 `beijiang`
3. 选 **Public**(Pages 免费版只能公开仓库)
4. 点 **Create repository**

> ⚠️ 公开仓库意味着**任何人拿到网址都能看到里面的钱数**。介意的话看下面「不想公开」一节。

### 2. 传文件

新仓库页面点 **uploading an existing file**,把这个文件夹里的**这 11 个文件**全部拖进去:

```
index.html
app.css
data.js
app.js
sync.js
ui.js
manifest.webmanifest
sw.js
icon-192.png
icon-512.png
apple-touch-icon.png
```

> 注意是**文件本身**,不要把外层文件夹拖进去(否则网址会多一层 `/北疆行程APP/`)。
> `README.md` 传不传都行,不影响功能。

拖完页面最下面点绿色的 **Commit changes**。

### 3. 开 Pages

仓库页 → **Settings** → 左侧 **Pages** → Source 选 **Deploy from a branch**,Branch 选 **main** + **/ (root)** → **Save**。

等 1~2 分钟刷新这一页,顶上会出现网址:

```
https://你的用户名.github.io/beijiang/
```

这就是发群里的地址。

### 4. 验证

用手机浏览器打开这个网址,能看到「D1 厦门 → 乌鲁木齐」就成了。

## 四、日常使用要点

| 事 | 说明 |
|---|---|
| **保存** | 自动。改完任何东西右下角会闪「保存中…」→「已保存」,不用手动点 |
| **同步** | 底栏 **☁ 同步**。配好之后有信号时点一下,大家的账就合到一起。按钮上会显示上次同步的时间。没配也不影响,就是个纯本地记账工具 |
| **导出** | 底栏「导出」→ iOS 会弹分享面板,选「存储到文件」或直接发微信给自己。**没配同步的话这是唯一的备份手段**,建议每天存一份 |
| **导入** | 选之前导出的 `.json` 覆盖当前数据。导入前的旧数据会在本地留一份 `xj_cost_prev` 兜底 |
| **重置** | ⚙ 里的「恢复初始数据」,**会清掉所有改动**,会二次确认。⚠️ 重置后再点同步,会把云端别人的账**拉回来**(不是把云端也清掉) |
| **房费刷新** | 「预订」页的刷新按钮只补**新订的天数**,不会覆盖你手填过的金额和付款人(手填过的条目左边有条橙线) |
| **统一结算** | 「分账」→ 成员下面选“统一结算给”。例如柠檬选巴巴后,个人垫付/应摊仍各自显示,但最简结算会把两人的净额合并成“巴巴（含柠檬）”统一收付 |

### 换手机 / 换浏览器怎么办

数据存在**浏览器本地**,不跟着账号走。换设备就是:老设备「导出」→ 把 json 发过去 → 新设备「导入」。
(配了下面的多人同步之后就不用这么麻烦了,新设备填一下 ⚙ 点同步就全回来了。)

### 清缓存会丢数据

Safari「清除历史记录与网站数据」会一起清掉。**所以才要经常导出。**

## 五、多人同步(可选,但强烈建议配)

不配也能用 —— 就是个各记各的本地工具,靠导出 json 互相发。配了之后,**每个人点一下 ☁ 同步,大家的账就合到一起**。

### 它是怎么工作的

- **离线优先**:记账永远是本地立刻生效,不联网照记不误
- **手动同步**:点 ☁ 同步 = 拉云端账本 → 跟本地**按条目合并** → 推回去
- **按条目合并,不是整份覆盖**:两个人在没信号的地方各记一笔,联网后**两笔都在**,不会互相顶掉
- **同一条被两个人都改了**:改得晚的那次赢(比时间戳)
- **删除会传播**:删掉的条目打墓碑标记同步出去,不会被别人的旧数据「复活」
- **账本就是仓库里一个 `ledger.json`**,每次同步是一次 commit —— 改坏了、误删了,能在 GitHub 的历史里翻回来

### 配置步骤(建一次,全队共用)

#### 1. 建一个**私有**数据仓库

跟放网页那个公开仓库**分开建**,专门存账本:

1. GitHub → **+** → **New repository**,名字比如 `beijiang-data`
2. 选 **Private**(账本里有钱数,别公开)
3. ⚠️ **务必勾上 `Add a README file`** —— 空仓库没有 `main` 分支,同步会一直报「找不到仓库或文件」
4. **Create repository**

#### 2. 建一个只能动这个仓库的令牌

GitHub 右上角头像 → **Settings** → 左侧最底下 **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**:

| 填什么 | 值 |
|---|---|
| Token name | 随便,比如 `beijiang` |
| Expiration | 设到**旅行结束之后**(过期了同步就会报「令牌无效」) |
| Repository access | 选 **Only select repositories** → 只勾 `beijiang-data` |
| Permissions → Repository permissions → **Contents** | **Read and write** |

其它权限一个都不要给。生成后令牌**只显示这一次**,复制下来。

> 🔒 **令牌绝对不能提交进任何仓库。**
> 一进公开仓库,几分钟内就会被人扫走;而且 GitHub 自己的 secret scanning 检测到会**直接把它吊销**,全队同步一起失效。
> 所以 App 里的令牌是**每个人在自己手机上手填一次**,只存在各自的 localStorage,永远不会被上传。

#### 3. 把令牌私下发给同伴

微信**私聊**发,或者当面扫。别发群里(群消息会被截图、被转发)。

#### 4. 每个人在 App 里填一次

点底栏 **⚙** → 填:

| 字段 | 填什么 |
|---|---|
| 我是谁 | 选自己的名字(新记的支出默认算在他头上) |
| GitHub 用户名 | 建 `beijiang-data` 那个人的用户名(不是自己的) |
| 仓库名 | `beijiang-data` |
| 分支 | `main` |
| 账本文件名 | `ledger.json` |
| 访问令牌 | 上面复制的那串 |

→ **保存** → **测试连接**,看到「连上了 ✓」就成了。

#### 5. 第一个人点一下 ☁ 同步

云端还没有 `ledger.json`,第一次同步会自动创建。之后其他人点同步就能拉到。

> 第二个人第一次同步时,他手里的默认数据和云端是**同一份**(内置条目的 id 是写死的),所以合并出来还是 9 天行程 10 条支出,**不会变成 18 天 20 条**。

### 同步报错对照

| 提示 | 什么意思 |
|---|---|
| ⚠️ 令牌无效或已过期 | 令牌填错了,或者过期了 —— 重新生成一个,大家重填 |
| ⚠️ 令牌权限不够 | Contents 权限没给 **Read and write**,或者没勾中这个仓库 |
| ⚠️ 找不到仓库或文件 | 用户名/仓库名拼错;或者仓库是空的(没勾 README,没有 main 分支) |
| ⚠️ GitHub 限流了 | 点太频繁,过几分钟再点 |
| ⚠️ 现在没网 | 就是没信号。**本地记账不受影响**,有信号了再点一次 |
| 连续 3 次都被别人抢先了 | 好几个人同时在点同步,过几秒再点 |

### 几个要注意的

- 令牌存在各自手机的浏览器里,**清缓存会连令牌一起清掉**,要重填(数据也会一起没,所以别清)
- 同步只在**点按钮**和**打开 App 时(⚙ 里那个勾选)**发生,不是实时的 —— 两个人同时在改同一条,后同步的那个人会看到自己的覆盖了对方的,这是设计如此
- 谁都可以改所有人的账,没有权限之分。这是给 5 个熟人用的工具,不是记账 SaaS

## 六、我改了代码,同伴那边怎么更新?

1. 改完文件重新传 GitHub
2. **必须把 `sw.js` 第 5 行的版本号 +1**:
   ```js
   var CACHE = 'beijiang-v5';   // → 改成 'beijiang-v6'
   ```
   不改的话 Service Worker 会一直用旧缓存,同伴永远看不到新版。
3. 同伴联网状态下打开一次会静默下载新版,**再开一次**生效(会弹「有新版本,关掉重开即可更新」)。

⚠️ 更新代码**不会**动同伴已经录入的数据 —— 数据存在 localStorage,跟代码文件是分开的。但如果改了 `data.js` 的默认行程结构,老数据可能对不上,那种情况下让大家先导出备份。

## 七、不想公开仓库怎么办

先分清两个仓库:

| 仓库 | 装什么 | 能不能私有 |
|---|---|---|
| 网页仓库(`beijiang`) | 代码,不含任何钱数 | GitHub Pages 免费版**必须公开** |
| 数据仓库(`beijiang-data`) | `ledger.json`,**钱都在这里** | **本来就该私有**,它走 API 不走 Pages,私有完全没问题 |

所以默认这套配下来,**账目本身是私有的**,公开的只有一份谁都看得懂的代码。真要连代码也不想公开:

- **Cloudflare Pages**:免费,支持私有仓库,还能加 Access 密码保护。国内访问速度比 GitHub Pages 稳。
- **Vercel / Netlify**:免费,私有仓库可以,但国内偶尔抽风。
- **腾讯云 / 阿里云静态网站托管**:几块钱一个月,国内最稳,要备案域名或者用它给的默认域名。
- **土办法**:仓库照样公开,但把网址里的仓库名起得没人猜得到(比如 `x7k2m9`)。安全性等于零,防君子不防小人 —— 不过说实话,一趟旅游的房费车费,也没人会去爬。

## 八、文件说明(改代码时看)

| 文件 | 干什么的 |
|---|---|
| `index.html` | 页面骨架、底栏、设置弹层、导出兜底弹层、Service Worker 注册 |
| `app.css` | 全部样式。iOS 三处关键处理:输入框 `font-size:16px`(防聚焦缩放)、`env(safe-area-inset-*)`(避开刘海/横条)、`-webkit-appearance:none` |
| `data.js` | 出厂默认数据(成员、9 天行程、车费参数、已录支出)。**里面的 id 必须是写死的常量** |
| `app.js` | 状态、localStorage 读写、老版本数据迁移、防抖自动保存、房费/车费/分账算法 |
| `sync.js` | 合并引擎 + GitHub Contents API 客户端。**账目算法一行都不在这里**,它只管把两份数据合成一份 |
| `ui.js` | 4 个页签的渲染、增删改事件、设置弹层、导入导出 |
| `manifest.webmanifest` | PWA 清单,决定主屏图标和名字。路径全是相对路径,所以放在 GitHub Pages 子目录也不会挂 |
| `sw.js` | Service Worker。导航和静态资源都是**缓存优先**,弱网下不会卡在超时上 |

### 数据结构(v4,为了同步做的改造)

每条成员/行程/支出都带这几个字段,少一个合并就会出问题:

| 字段 | 干什么的 |
|---|---|
| `id` | 稳定 id,**创建后永不变**。合并就是按它对齐的 —— 改名字、改金额都不会让它变成「另一条」 |
| `mt` | 最后修改时间戳。合并时同 id 比大小,晚的赢 |
| `by` | 最后改它的设备号。同一毫秒撞车时按它裁决,保证两台设备算出同样的结果 |
| `del` | 墓碑。删除不是真删,是打标记 —— 真删的话别人的旧数据一同步就把它复活了 |
| `seq` | 创建序号,决定显示顺序。**合并后必须按 `(seq, id)` 排序**:两台设备排出的顺序必须完全一样,否则内容明明一致却比不出相等,双方会无限互相提交 commit |
| `settleTo` | 成员可选的结算代表 id。缺失=本人结算;例如 `m2.settleTo="m1"` 表示 m2 最后的应收/应付并入 m1。它随成员条目一起同步,不复制到支出里 |

### 统一结算规则

- 绑定**只影响“最简结算方案”**,不修改每人的已垫付、应分摊、净额,也不修改支出的真实付款人。
- 多人可以绑定同一个代表;A→B→C 这种链最终统一归到 C。
- 删除代表时,直接绑定到他的人自动恢复本人结算;更远链条落到最后有效成员。
- 两台设备并发改出循环时,App 按稳定成员顺序自动选一个代表,各设备会算出同一个结果;本机手动设置时会直接阻止循环。

⚠️ 往 `data.js` 里加内置条目时,**id 要手写**,不要用随机数/时间戳。
5 个人第一次打开拿到的都是这份默认数据,id 随机的话一同步就会合并出 5 份重复的行程。

引用关系也全部走 id:支出的 `payer` / `share` 存的是成员 id(不是名字),`dayId` 存的是行程 id。
所以**改名字不会影响账目** —— 账记的是人,不是名字。

## 九、分账口径

- **房费**:每天单人价 × 参与人数;某天多条房费(拆了付款人)时,金额一律不自动改
- **车费**:按 `油费 + 过路费 + 租车费` 分摊,不参团的人(`noTrip`)不摊
- **净额**:`已垫付 − 应摊`。为了不出现「每人四舍五入后总和差一两分」,计算全程不提前 round,只在显示时保留两位
- **结算**:先按 `settleTo` 把绑定成员的净额并入结算代表,再用贪心算法(最大债务组 → 最大债权组),让实际付款人用尽量少的转账全部结清
